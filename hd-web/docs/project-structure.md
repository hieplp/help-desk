# Project structure

TanStack Start + React + TanStack Router + Tailwind. File-based routing. Matches `../../docs/features.md`.

## Root

```
hd-web/
  package.json
  vite.config.ts
  tsconfig.json
  tsr.config.json
  src/
  docs/
```

`node_modules/`, `dist/`, `.vite/`, `routeTree.gen.ts` (after generate) are generated or ignored.

## Code

```
src/
  router.tsx          getRouter, TanStack setup
  routeTree.gen.ts    generated by tsr; never edit
  routes/             file-based routes; thin wrappers only
    __root.tsx        shell, theme init script
    index.tsx
    login.tsx
  features/
    auth/
      session.ts      zustand store + persist
      login/          page + local components/hooks/schema
        index.tsx
        schema.ts
        components/
        hooks/
    tickets/
      new/            create-ticket page + form/hook/schema
  api/
    client.ts         fetch wrapper; all HTTP goes here
  components/         shared UI
    fields/           FormField
  styles.css          demo-* classes, CSS vars, theme
```

- A route file imports a feature page and passes it to `createFileRoute`.
- A feature page owns its layout and calls `api.*`; it may have local `components/`, `hooks/`, `schema.ts`.
- `api/` is the only place that does fetch. Features import from it.
- `components/` is feature-agnostic. No feature may put its private UI here.
- Routes never call `api/` or hold state.

## Routes

File-based. `bun run generate-routes` (tsr generate) rebuilds `routeTree.gen.ts`.

Protected pages redirect in the component using session; server enforces.

## Not used

- No state library beyond zustand (session only).
- No CSS modules, styled-components, or per-file CSS.
- No test setup.
- No server components or API routes yet (TanStack Start SSR only for shell).
- No raw `fetch` outside `api/client.ts`.
- No route params or search for tokens.
